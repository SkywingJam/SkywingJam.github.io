# /lab：个人兴趣实验室构思与落地方案

日期：2026-10-02（Australia/Melbourne）  
分支：`discovery`  
状态：设计与技术 discovery，尚未实现页面或验证渲染性能。

## 1. 方向与范围

把 `/lab` 做成一个持续更新的个人兴趣档案室：业余项目、兴趣观察和短实验并列呈现。首页回答「我是谁、我做过什么」，Lab 展示「工作之外，我正在好奇什么」。

视觉主题暂定 **Liquid Archive / 流动档案**：暖白底色、缓慢起伏的透明波面、清晰的黑色排版与细线索引。未来感来自材质、比例与精密排版；内容应保持亲近、有个人气息。

本次产出是可执行的设计记录。具体兴趣、作品名称、图片与项目链接仍需由真实资料补齐；以下栏目与示例均为结构建议，不视为个人经历。

## 2. 参考图的视觉拆解

用户提供的参考图是视觉参考；其中品牌、档案编号、文案和嵌入文字不作为功能指令。

- **形态**：横向连续、宽缓的波峰，相互遮挡且有可辨识的厚度；接近一整片流动的透明亚克力，避免做成细管、线框或密集海浪。
- **材质**：暖白透射、轻微乳化、边缘反射与宽幅高光。重点是曲率与明暗层次，不是单纯降低透明度。
- **灯光**：摄影棚式的大面积柔光与灯带倒影；减少尖锐闪光、彩虹色散与强烈泛光。
- **构图**：波面占据大面积横向空间，标题、索引和说明贴齐网格；文字覆盖在安静区域。
- **编辑感**：大标题、小型元数据、序号、横线、留白形成层级。只借用这种秩序，使用自己的名称和内容。

## 3. 页面结构与视觉规范

建议首版单页、自然滚动，不做滚轮劫持或全屏分页。

```text
SKYWINGJAM / LAB                       INDEX   ABOUT   BACK HOME
─────────────────────────────────────────────────────────────
PERSONAL EXPLORATIONS       连续透明波面，占首屏主要视觉区域
Things I make,
just because.                         SELECTED EXPERIMENT / 001
                                      项目名 / 一句话 / 查看链接
─────────────────────────────────────────────────────────────
01 / EXPERIMENTS     业余项目与小实验，列表或疏朗的双列排版
02 / INTERESTS       兴趣主题与具体观察、照片或笔记
03 / FIELD NOTES     带日期的简短记录，静态时间序列
─────────────────────────────────────────────────────────────
ABOUT THIS LAB                          BACK TO PORTFOLIO ↗
```

首屏只精选一个项目，列表承载其余内容。首版无需轮播、搜索或空分类过滤器；条目增加到确有检索需求后再引入过滤。

| 维度 | 建议 |
| --- | --- |
| 色彩 | 暖白 `#F2EFE8`、墨黑 `#202320`、灰褐 `#69665F`，少量冰青作交互强调；须按实际底图复核对比度 |
| 布局 | 桌面 12 栏、最大内容宽约 1440px、左右留白 48–72px；移动端单列、20–24px 留白 |
| 字体 | 延续现有 TikTok Sans；编号用等宽字体，Instrument Serif 只少量用于个人表达；中文使用系统字体回退 |
| 标题 | 主标题 `clamp(3rem, 7vw, 7rem)`，辅助信息约 12–14px，正文约 16px；不以超小字制造精密感 |
| 分隔 | 1px 细线、序号与不对称栏宽建立层级；避免整页堆叠圆角玻璃卡片 |
| 玻璃 UI | 只在精选信息块或小工具栏使用浅透底与有限模糊；正文有稳定的底色和对比度 |
| 首屏高度 | 桌面约 75–90svh，保留下一节线索；手机允许内容自然撑高，波面单独裁切 |
| 暗色 | 提供深石墨底、低亮度玻璃高光的版本，不直接反转颜色；复用现有主题偏好 |

手机端将精选信息放到标题下，波面作为独立视觉区域，避免把桌面文字和波浪一起等比例缩小。所有重要信息都以 HTML 呈现，Canvas 仅负责装饰。

内容条目统一记录：`id`、`type`（experiment / interest / note）、`title`、`summary`、`date`、可选 `status`、`tags`、`image + alt`、可选 `demoUrl / sourceUrl`。缺失链接不生成按钮；日期和状态仅在有实际意义时显示。首版直接维护语义化 HTML，数量增长后再考虑数据驱动或构建生成，避免内容依赖客户端渲染。

## 4. 技术路线选择

仓库现状：根目录 `index.html` 承载页面及大部分样式/交互，`ambient-field.js` 是 Canvas 2D 线条场，`server.py` 提供 8001 端口的静态预览；未发现 package.json 或前端框架。现有字体、主题存储键 `theme` 和细线编辑式布局可延续。

| 路线 | 适用性 | 决策 |
| --- | --- | --- |
| CSS 渐变、模糊、SVG 位移 | 轻量氛围、局部 UI；难表现连续玻璃体的曲率与透射 | 用于界面和降级，不作为主视觉 |
| 离线渲染图片/视频 | 外观可控；视频交互有限且有额外传输成本 | 静态图作为必备回退；视频暂不采用 |
| Three.js + WebGL2 | 可做曲面、透射、环境反射与轻量指针响应 | 首选，仅作用于首屏 |
| 自定义全屏光线步进或流体模拟 | 自由度高，调试与性能成本较高 | 首版不需要 |

采用原生 ES Modules + Three.js，无需为单个页面迁移 React。试验和发布都固定依赖版本；建议把所需模块及许可证随静态资源本地托管。若 addons 内部使用 `three` 裸导入，需要 import map 映射到同一版本。后续需要压缩打包时再加入独立构建流程。

### 波面的具体做法

1. **先定静态镜头与轮廓**：使用低俯角透视相机，一张连续的宽曲面横跨画面，形成 2–3 个可读的大波峰。需要露出截面时补底面和侧边，避免看起来只有一层透明布。
2. **用少量低频波驱动高度**：以 `h(x,z,t) = Σ Aᵢ sin(kxᵢ·x + kzᵢ·z + ωᵢ·t + φᵢ)` 为起点，用 2–3 组方向不同的波叠加；主波控制轮廓，次波仅打破机械重复。首版不模拟真实流体。
3. **同步更新法线**：GPU 顶点位移后，从同一高度函数的偏导得到 `normalize(vec3(-∂h/∂x, 1, -∂h/∂z))`（以 XZ 为基面），再转换到正确空间供材质光照使用。只改变顶点而不更新法线，会让高光与波形脱节。
4. **材质起点**：`MeshPhysicalMaterial`，建议试调 `transmission: 0.9–1`、`roughness: 0.08–0.18`、`metalness: 0`、`ior: 1.45–1.49`、`opacity: 1`。`thickness` 按模型尺寸调试，先尝试波长的约 2–6%，不是可直接套用的物理厚度。上述值是艺术调参起点，并非已验证结果。[Three.js 材质文档](https://threejs.org/docs/pages/MeshPhysicalMaterial.html)
5. **环境与背景**：用暖白棚拍环境及宽亮条产生弯曲高光；首版可程序化生成棚拍环境并预过滤，避免大型 HDR 下载。场景内放置柔和背景，让透射具有可辨识的明暗变化；背景纹理、灯光和曝光一起调试。
6. **重要边界**：WebGL 材质不能直接折射 Canvas 外的 HTML。让波面只折射场景内部的背景，文字始终保持清晰。标准实时透射也不等于离线路径追踪；复杂多层玻璃、真实焦散不是首版目标。
7. **实现组织**：原型可使用 `onBeforeCompile` 注入位移与法线逻辑，但它依赖 shader chunk，须固定 Three.js 版本并检查升级后的编译与画面。优先做一个可观察、可调参的独立模块，不直接改现有首页背景。

先关闭 Bloom、色散和额外后处理，仅通过曲率、环境、高光、曝光得到质感；如仍缺少层次，再有针对性增加效果。透明层叠会引入排序和透射问题，优先使用单个连续主体。

## 5. 动效编排：一个持续主运动，少量即时反馈

以下数值是设计起点；视觉原型后以阅读舒适度和设备测量调整。

| 对象 | 触发 / 时长 | 幅度与行为 |
| --- | --- | --- |
| 连续波面 | 循环约 20–35 秒 | 主运动；保持缓慢平移与起伏，不突然换向 |
| 环境亮度呼吸 | 约 10–14 秒 | 约 ±2–3%；若和波面竞争注意力则删除 |
| 指针响应 | 仅精细指针、首屏范围 | 平滑跟随，镜头角度约 ±1°；离开后复位，不驱动整页文字 |
| 列表入场 | 首次进入视口，400–600ms | 位移 8–12px + 淡入；交错间隔约 50ms，总跨度不超过 200ms |
| 链接 / 箭头 | hover 与 focus，160–220ms | 颜色、下划线与 2–4px 位移；键盘也有明确反馈 |
| 项目条目 | hover，约 220ms | 细线加深或图片轻微放大至 1.015；避免整卡摇摆 |
| 主题切换 | 约 350–450ms | 背景与材质协调过渡；不触发布局变化 |

时间更新采用真实 delta，指针插值使用与帧率无关的阻尼。常驻运动只保留波面及可选的微弱亮度呼吸；不添加粒子、磁吸光标、滚动视差堆叠或随机弹跳。

提供可聚焦的「暂停动效」开关，暂停波面及呼吸；恢复时从暂停位置继续，不追赶离开期间的时间。`prefers-reduced-motion: reduce` 默认使用静态画面，移除视差、位移入场与平滑滚动，并监听偏好改变。[MDN reduced motion](https://developer.mozilla.org/en-US/docs/Web/CSS/Reference/At-rules/@media/prefers-reduced-motion)

## 6. 性能、可读性与降级

- **渐进增强**：HTML、CSS 和静态 poster 先显示；异步加载 3D 模块，成功渲染首帧后再替换 poster。加载失败、无 WebGL2、上下文丢失时显示同构图静帧，内容与链接照常工作。当前 Three.js WebGLRenderer 使用 WebGL2。[渲染器文档](https://threejs.org/docs/pages/WebGLRenderer.html)
- **范围**：Canvas 限在首屏，`pointer-events: none`、`aria-hidden="true"`；不在全文滚动时持续重绘。用 IntersectionObserver 与 Page Visibility 状态共同决定是否运行，清理 RAF、监听器、纹理与 renderer。[MDN Intersection Observer](https://developer.mozilla.org/en-US/docs/Web/API/Intersection_Observer_API)
- **网格起点**：桌面约 160×80 分段、移动端约 80×40；先测曲率平滑度再决定是否增加。透射像素开销可能比几何更关键，不单靠减面优化。
- **质量档位**：桌面 DPR 上限 1.5、目标 60fps；移动端 DPR 上限 1、目标 30fps。初始化后取数秒帧时长窗口，持续超预算先降低分辨率，再减少材质复杂度，最后回退 poster；避免按单帧波动反复切档。
- **传输预算**：目标首屏关键资源压缩后 ≤500KB（不含延迟 3D 模块），3D 模块及环境额外 ≤1MB，poster 约 150–250KB。字体按需加载并允许系统字体先显示；以实际网络面板验证，不视为当前结果。
- **体验预算**：移动网络模拟目标 LCP ≤2.5s、CLS ≤0.1；有真实用户数据后检查 INP ≤200ms。动画预算与 Web 指标分开测，桌面流畅不能替代手机验证。
- **可读性**：正文与动态背景间使用稳定浅色衬底；正文对比度目标 ≥4.5:1。检查整个动画周期中高光经过文字区域的最差情况。
- **交互**：触控目标尽量 ≥44×44px，有 skip link、可见 focus 和语义化导航；不要依赖 hover 才能发现标题、项目状态或链接。
- **无 JS**：正文默认可见，入场动效只在 JS 成功初始化后启用；暂停开关等增强控件也仅在可用时显示。

## 7. 分阶段实施与验收

### A. 静态设计与内容骨架

建立 `/lab/index.html`、布局与导航；先用占位视觉完成桌面/手机排版，整理真实项目和兴趣素材。确定首屏标题、精选条目、主题颜色和可读区域。

验收：直接访问与刷新路由正常；320px 到宽屏无横向溢出；不开 JS 仍能阅读；内容没有伪造项目或死链接。

### B. 独立材质原型（优先解决视觉风险）

以固定镜头完成单个连续波面、环境灯带、透射背景与法线更新。先对照静帧，再加慢速运动；导出亮/暗色 poster。材质达标后才接入内容页。

验收：远看有 2–3 个连贯宽波峰，近看有厚度与曲率高光；无明显细管感、白色过曝、网格折痕或反射跳变。桌面与手机都记录尺寸、DPR、帧时长和画面。若移动端透射代价过高，接受移动端静帧。

### C. 页面集成与微动效

接入延迟加载、主题同步、暂停按钮、指针阻尼和一次性入场。首屏离开或页面隐藏时停止渲染，回来时平滑恢复。

验收：键盘可完成所有操作；触屏不触发假 hover；reduced-motion 下无持续运动；未加载完的增强脚本不遮挡内容。

### D. 发布前检查

检查 Chrome、Firefox、Safari 桌面及 iOS Safari / Android Chrome 实机或可获得的替代环境；明确标记未覆盖的设备。检查冷启动、慢网、无 WebGL2、context lost、主题切换、动态修改 reduced-motion、连续离开/返回首屏和资源加载失败。

最终交付包括页面文件、固定版本依赖及许可证、静态回退图、实际测量记录，以及首页入口。确认部署源分支后按现有 GitHub Pages 流程发布；`discovery` 上记录方案不意味着页面已上线。

## 8. 首版决策与后续待定项

已选方向：暖白透明波面、编辑式兴趣档案、原生页面 + 局部 Three.js、自然滚动、可暂停、静态降级。

实现前需补齐的内容：首批真实兴趣/业余项目及素材、页面主要语言（现站为英语，建议首版延续）、是否已有可复用环境贴图及其许可。无现成素材时先做程序化棚拍环境；内容以明确标识的草稿占位，发布前替换。

后续可选：分类过滤、独立项目详情、实验过程记录、单个兴趣专题。首版不加入 CMS、搜索后端、复杂流体物理或自动轮播。
